# v0.33.16-fx-fast：瞬态特效中心点视野快速路径

**已部署。** 用户批准的方案：开火卡顿（玩家与敌人持续射击）根因为海量短命特效
（Part/子弹/弹壳/火花）逐对象 Shape 遮罩 + cacheAsBitmap 的动态重建与 Alpha 合成。
本轮把瞬态特效改为"中心点视野查表二值处理"：亮区摘遮罩原生直绘，暗区挂常驻
空 Shape 遮罩；由 `fx_vision_quality`（0=快速默认 / 1=原画质）可配置回退。

  `AEA30314…9AA557` + 旧 config）。重启游戏生效。

## 实现（build/fx-fast-20261102/src，自 production-combo-v4 冻结派生）

1. `applyWorldVisuals` 链表循环按 `cfgFxQuality` 分流：快速档走新函数
   `applyTransientVisual`，质量档 1 保持原 `applyWorldVisual` 逐对象遮罩。
   狮鹫手臂/实体武器仍走原遮罩路径不变。
2. `applyTransientVisual`：`fxCenterLit`（中心点查 `currentSight`（current）或
   `fogCache`+`MASK_LIT_A` 阈值（classic/兜底），与掩膜同数据源，记忆区计为
   不可见）→ 亮区 `releaseWorldVisual` 摘遮罩；暗区登记
   `{shape:空Shape,baseMask,cache}` 并挂 `visual.mask=shape`（复用既有
   record 生命周期：pass 标记、applyWorldVisuals 末尾清理、
   restoreWorldVisuals 统一恢复）。
3. **不碰 visible/alpha**：原生 `Part.step` 的 otklad 机制会把 `vis.visible==false`
   的粒子每帧设回 true，visible 开关方案在与原生 step 的执行顺序上不可靠
   （本轮实现前发现的坑，方案阶段原设想的 visible 开关已废弃）；mask 是常驻
   显示属性，与监听顺序无关。空遮罩完全隐藏语义沿用 v0.33.10 起已验证的
   drawDark 路径。视野场未建立时保持原生可见（与原路径无场兜底一致）。
4. `loadConfig/saveConfig` 增加 `fx_vision_quality`（0/1，非法值忽略，默认 0）。
   VERSION → `v0.33.16-fx-fast`。

语义取舍（用户已批准）：跨明暗边界的特效由软羽化渐变改为按中心点二值切换；
暗区中中心点在亮侧的子弹尾迹可能探入边界几个像素（视觉证据见下，占比 <0.1%）。

## 边界与遗留

- 本轮只测 current 模式（用户主用与主诉模式）；classic 的快速路径走同一
  fxCenterLit 兜底分支但未做整窗计时，如需可后续补 classic A/B。
- 快速档下跨边界特效无羽化渐变；`fx_vision_quality=1` 完整回退原行为。
- 34 号正序轮的 128ms 单帧与 36 轮的 119ms 尾帧均为孤立长帧（RV 当帧
  0.6–3.4ms，非 RV 段），与既有"长帧分布于绘制后等待/GC"结论一致，不在
  本轮修复范围。
- 移动端到端帧距（含 wall/fog 更新）仍有 RV 3.35ms 剩余成本，属后续
  wall-surface/fog 方向，与特效路径无关。
- 环境：与并行"本体开火全面普查"会话共享测试登记（其 49–56 轮并行运行），
  本轮 33–36 均登记"通过"；mask-budget 旧链在本机已不可用（player-seed 流程
  在当前宿主 #1009，且 python 需 PYTHONUTF8=1），失败记录保留在
  mask-budget-output/32-fx-fast（三轮启动失败，未产生性能样本）。
