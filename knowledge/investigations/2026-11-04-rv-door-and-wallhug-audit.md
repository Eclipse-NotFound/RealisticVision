## 1. 问题 A（门/窗边界）逐问回答

### Q1 `computeFov` 的瓦片中心一次 castRay、三级阈值与 40px 补丁

**做法（已确定）**：
- 眼点来自 `playerVisionEye`（`1788-1799`）；视半径 `r = locDist2`（`1802-1811`），`fov[]` 先全清 `FOV_NONE`（`1812`）。
- 对半径窗口内**每个瓦片只投一条射线到该瓦片中心** `(cx,cy)=((tx+0.5)*40,(ty+0.5)*40)`（`1815-1829`）。
- 距离衰减 `distFalloff` 与 `br=lit*falloff`、`litArr` 都写入数组（`1831-1838`），**但 `br`/`litArr` 全文件再无读取**
  （唯二写入在 `1837-1838`、`1887-1888`，初始化在 `1221-1243`；无任何读点）。**“连续亮度”被算了却丢弃**。
- 归类阈值只有两个：
  - `lit >= cfgLitMin` → `FOV_VISIBLE`（`1839-1843`）；
  - `lit > 0.0001` → `FOV_DIM`（`1844-1848`）；
  - 否则 `FOV_NONE`（`1849-1851`）。
  `cfgLitMin` 默认 0.6（`103`），生效 0.6。判定量是 `lit`（射线剩余亮度），**不是** `br`，所以距离衰减不改变分类。

**会不会在门/窗锥体产生 40px 尺度补丁：会，而且是主因之一。**
`fov[]` 一个瓦片一个类，`fillFogCache` 再按“类 + 4 角分类”选下面 6 条渲染分支之一（`2299-2375`）：

| 分支 | 条件 | 结果 |
|---|---|---|
| 墙 | `t.opac >= 1`（`2304-2307`） | `fillWallTile`（走原生光场） |
| 门景 DIM | `f==FOV_DIM`（`2309-2313`） | `recalcTile(...,doorF,dimA,cs,true)` 逐子格射线 + **平顶 floor=doordim** |
| 可见全亮 | `f==VISIBLE && cLit==4`（`2363-2366`） | `fillLitTile`：**完全不做射线**，只算 `distFalloff` |
| 可见混合 | 其余 VISIBLE | `recalcTile(...,dimF,...)` 逐子格射线 + floor=dim |
| 全暗 | `f!=VISIBLE && cLit==0 && (flags&240)==0`（`2368-2371`） | `fillMemoryTile` 整瓦片 dimA/黑 |
| 其余 | （`2374`） | `recalcTile(...,dimF,...)` |

因此同一个 40px 瓦片只能在“门景平顶”“距离衰减”“记忆暗色”“全黑”里选一种；相邻瓦片因**中心射线穿过的透光格数**不同而换模型，
即使真实照明在瓦片边界上是连续的，也会在 tile 边界上断成 40px 台阶。门景锥体里最尖锐的例子：
木门背后 `lit=0.2`（DIM 平顶 38）与窗外 `lit=0.8`（VISIBLE 快路径，甚至 0）只差一条射线是否穿过 0.8 的门。

> 另外注意：门/窗瓦片**自身**作为射线终点时会被扣两次 opac（见 §2.1/A-5），
> 使 `window` 瓦片自身 `lit=1-0.2-0.2=0.6000000000000001`，恰好比 `cfgLitMin=Number("0.6")` 大 1 ulp → 仍是 VISIBLE（浮点临界，见 §4 M5）。

### Q2 门景口径 vs 墙口径（采样粒度/alpha 公式/亮度来源对比）

**结论：门景的“分类”是瓦片级，像素是子格级；墙是角点级 + 另一套亮度源。两者不是同一算法换采样密度，而是两套模型。**

| 维度 | 门/窗 FOV_DIM（木门 0.8） | 门/窗 FOV_VISIBLE（窗 0.2、栅格 0.1、门 0.3） | 墙 |
|---|---|---|---|
| 分类单位 | 1 瓦片 1 条中心射线（`1815-1852`）→ `fov`；之后整瓦片逐子格射线 | 同左，另加 4 角分类 `cLit/flags`（`2314-2362`） | **4 个瓦片角**（`wallCornerAlpha` `2691-2696`，`fillWallTile` `2712-2715`）；无射线 |
| 采样粒度 | 子格 `40/fogSub`：生效 **10px**（`2403-2408`；fogSub=4，`693`） | `fillLitTile` 无射线（只按 `distFalloff` 逐子格，`2495-2513`）；混合瓦片 10px | 角点 40px 晶格双线性 → 子格 10px 写入；显示层 `wallRaw` **1px/瓦片**再 ×40 双线性放大（`1411-1421`，`1416` `smoothing=true`）；RVWallSurface 另有 **5px** 面采样 + 32px 深度核（`RVWallSurface.as:18-22,84-95,629-651`） |
| alpha 公式 | `round((1-max(lit*falloff,cfgDoorDim))*255)`（`2427-2435`） | 快路径：`round((1-max(falloff,dimF))*255)`，**`lit` 被丢弃**（`2503-2510`）；混合：`round((1-max(lit*falloff,dimF))*255)`（`2437-2445`） | `round(255-(255-gameA)*(1-cur+cur*cfgDim))`，`gameA=(1-light)*255`（`1719`、`2614-2626`） |
| 亮度来源 | `castRay` 的 `lit` × `distFalloff`（`1899-2052`、`3267-3279`） | 同左，或被丢弃 | **原生 `tile.visi`**（`Location.as:3108-3238`；`explorationLight` `301-309`）+ 记忆进度，无射线、无距离衰减 |
| 距离衰减 | 有，但被 `doorF` 下限压平 | 有；`lDist1=300` 内直接 alpha 0（`2486-2494`） | **无**距离衰减 |
| 记忆/下限 | 亮子格 = 38 平顶；被挡子格 = 记忆 102 或黑 255（`2447-2454`） | 记忆 102/黑 255；掩膜下限硬编码 0.35（`2458`、`2511`） | 记忆 = `light*cfgDim` 亮度；掩膜路径 `personalWallAlpha` **硬编码 0.35**（`2705`、`2717-2720`） |
| 模糊 | `curBlur` 2.5 雾 px = **25 世界 px**（生效 soft=25；`702`、`738`、`2256`）；墙不经过雾模糊 | 同左 | 不经过雾模糊；由 40× 双线性 + RVWallSurface 轮廓（`329-401`）平滑 |
| 显示层 | `fogBitmap`（`floorClip` 掩膜，`1436`） | 同左 | `wallBmp`（`wallClip` 掩膜，`1446`）+ `fogShadow` 轮廓（`2631-2669`） |
| 边界形态 | 10px 阶梯 + 平顶 + 25px 模糊 + 瓦片级模型切换 | 0 / 26 / 51 / 77 / 102 的 40px 补丁 | 连续双线性 + 5px 轮廓 + 原生光场（`updVisi` 每帧 0.1 缓动，`Tile.as:271-279`） |

**直观后果**：门/窗路径的像素采样其实比墙*更细*（10px vs 40px 晶格），但它看起来更差，原因不是采样密度，而是
**平顶常量下限 + 瓦片级模型切换 + 丢弃 `lit` 的快路径 + 与墙不同的亮度源**。所以“把子格从 4 提到 8 / 加大模糊”不会解决 A。

### Q3 DIM 平顶：是不是 38 恒定？跳变多少级？

用**生效配置**（doordim=0.85，dim=0.6）逐行算：

- `recalcTile` 的 `doorView && lit>0.0001` 分支（`2427-2436`）：
  `br = max(lit*falloff, 0.85)`；`a = round((1-br)*255)`。
- 木门 opac=0.8：门后 `lit=0.2`（射线单次穿过门），`lit*falloff ≤ 0.2 < 0.85` → **每个亮子格 a 恒等于 `round(0.15*255)=38`**。
  多层木门/水组合（`lit→0`，经 `2047-2049` 的 `leaked` 分支返回 0.05）同样是 38。
- 只有“中心射线穿门、但该子格射线没穿门”的**无衰减缝隙**（`lit≈1`）才会低于 38（`falloff` 直接给 0…38）。
  这种子格是锥体边缘的少数，反而让平顶内部出现 10px 的硬缝。
- 若把 doordim 当源默认 0.5：同样恒等于 `round(0.5*255)=128`；由 0.5/0.85 可见**平顶问题与具体值无关，值只决定平顶多亮**。

**跳变级数**（门平顶 38 为基准，生效值）：

| 相邻对象 | alpha | 与 38 的差 |
|---|---|---|
| 全亮（`fillLitTile` 内、`lDist1` 内） | 0 | **38** |
| 窗锥混合边缘（`lit=0.8`） | 51 | 13 |
| 门景锥边缘（中心 NONE、角有光 → `recalcTile(dimF)`） | 102 | **64** |
| 记忆区 `dimA` | 102 | 64 |
| 未探索/未见过 | 255 | 217 |
| 可见墙（原生 light=1） | 0 | 38 |
| 可见墙（light=0.5） | 128 | 90 |
| 记忆墙（light=1, dim=0.6） | 102 | 64 |
| （若 dim 仍为源默认 0.35：记忆=166，则 166−38=**128**） | 166 | 128 |

> 所以你的估算“38 vs dimA”成立，但那个 166 是 dim=0.35 的 `dimA`；**生效 dim=0.6 → dimA=102，跳变是 64 级**。
> 注意 38（亮度 0.85）比 102（亮度 0.6）**更亮**：门/窗锥体比周围“记忆暗色/锥边缘”更亮，明暗序是反的，
> 这正是“门/窗边界看起来比墙突兀”的量化来源。平顶与平顶之间只由 25px 模糊软化，40px 的瓦片边界仍然可见。

### Q4 三个“下限”的默认值、量纲与打架点

**量纲**：`cfgDim`、`cfgDoorDim` 都是**亮度**（0=全黑，1=全亮），不是暗度；转换到雾 alpha 时统一取 `(1-亮度)*255`。
源默认 `dim=0.35`（`76`）、`doordim=0.5`（`102`，注释“比记忆暗色亮”）；**生效** `dim=0.6`、`doordim=0.85`（见 §0.1）。
`cfgLitMin` 只用作可见阈值（`1839`），不参与 alpha。

参与点：

| 处 | 用到什么 | 行号 |
|---|---|---|
| `recalcTile` 门景/普通显示 | `floorF`（调用方传 `doorF` 或 `dimF`） | `2311`（doorF）、`2374/2365`（dimF）、`2431-2435`、`2441-2445` |
| `recalcTile` 单位可见场 `currentSight` | **硬编码 0.35**（非 doorView 分支；`logicalA`） | `2458` |
| `fillLitTile` 显示 | `dimF` 下限 | `2505-2510` |
| `fillLitTile` `currentSight` | **硬编码 0.35**，且只用 `falloff`（`lit` 已丢） | `2504`、`2511` |
| `fillWallTile` 墙 alpha | `wallA` 四角（其计算用 `cfgDim`） | `2614-2626`、`1719` |
| `fillWallTile` 掩膜路径 `personalWallAlpha` | **硬编码 0.35**；且由 `cfgDim == 0.35` 的精确比较决定是否启用 | `2705`、`2717-2720` |
| classic `tileFogAlpha` | `cfgDoorDim` 作为整瓦片亮度下限 | `2517-2532`（尤其 `2528-2531`） |
| classic 双场 | `displayGrey=round(255*cfgDim)` vs `canonicalGrey=round(255*0.35)` | `2866-2867`、`2887-2888` |
| `wallEdgeLight` | DIM 瓦片用 `cfgDoorDim` 抬亮 | `2687` |

**打架点（按生效配置排序）**：

1. **序反转**：`doorF=0.85`（38）亮于 `dimF=0.6`（102）与记忆 102。门景本应更暗，实际更亮 → 门/窗锥体是“亮补丁”。
2. **`cfgDim != 0.35` 使硬编码 0.35 全部激活**：生效 dim=0.6 →
   - `fillWallTile` 走 `personalWallAlpha`（`2717-2720`），而它用 0.35（`2705`）；
   - 墙的**显示** alpha 用 `wallA`（dim=0.6）：light=1 时显示 102、掩膜当 166；light=0.5 时显示 179、掩膜当 210；
   - 于是**墙显示亮度与墙掩膜/单位遮挡口径不一致**，差值 31～64 alpha 级。
3. **视角/掩膜口径**：`fillLitTile` 显示下限 0.6，`currentSight` 用 0.35（`2504`、`2511`）；
   `recalcTile` 门景显示 0.85、掩膜用 `doorF`（`2458`，即 0.85）——门景反而一致，普通区不一致。
   当用户调 dim 时，雾和单位显隐会以两套下限漂移（部署值 0.6 已经在漂移）。
4. **classic 有第三套**：`displayGrey` 跟着 dim，`canonicalGrey` 固定 0.35（`2866-2867`）。生效 current 不触发，但 F12 切 classic 会看到另一种门景（`tileFogAlpha` 把整瓦片抬到 doordim，`2528-2531`）。
5. **配置健壮性**：`dim` 有 0..1 夹取（`602`），但 `doordim`/`litmin` 直接 `Number(val)`（`607-614`）；越界可产生负 alpha（`2435`），`BitmapData.setPixel32` 的负值行为待证（应属“坏配置”，非本缺陷主因）。

### Q5 `fogSub` 与 `curBlur` 在两条路径上的实际像素粒度

- 生效 `vision_quality_preset=0` + `fog_vision_quality=0` → `fogSub=4`（`693`；字段初值 8 在 `145`，会被覆盖）。
  **1 子格 = 40/4 = 10 世界 px**。preset 1/2 或 `fog_vision_quality=1` 才 8（5px）。
- **门/窗路径**：瓦片类 40px；`recalcTile` 和 DIM 分支逐 **10px** 子格射线（`2403-2412`）；`fillLitTile` 无射线、只按 10px 子格算 `distFalloff`（`2495-2513`）。
- **墙路径**：4 个 **40px** 角采样 + 双线性（`2712-2745`）；显示层 `wallRaw` 1px/40px 双线性（`1411-1421`）；`RVWallSurface` 暴露面 **5px** 采样、沿法线 `DEPTH=32`、`BRIGHT=12`、`FRINGE=10` 的核（`RVWallSurface.as:18-22,84-95,629-651`）。
- **模糊是否一致**：`curBlur` 只在 `applyVision` 里对整张 `fogRaw→fogBmp` 应用一次（`2253-2258`），
  所以门景与地板/窗路径**用同一个模糊**；墙是独立图层（`1411-1446`）**不经过这个模糊**，靠 40× 双线性和 RVWallSurface 轮廓。
  生效 `soft_current=25` → `curBlur = 25*(fogSub/8)/5 = 2.5` 雾 px = **25 世界 px**（`702`；`738` 同式），
  不是注释里写的 “4.0 / ≈32px”（`450`、`1374` 的注释已过时）。

### Q6 角点复用缓存 `cornerReuseC/Flags`

**复用条件**（`2277-2279`）：`cornerReuseValid && cornerReuseLoc===loc && eyeX/eyeY 完全相等 && int(frameCount)-cornerReuseFrame <= 4`。
只有在“非复用”分支才写缓存（`2331-2362`）。而：
- 墙瓦片在 `2304-2307` 就 `continue`，不写；
- **`FOV_DIM` 瓦片在 `2309-2313` 就 `continue`，不写**；
- `reusedTiles` 只加 1 不读（`2280`、`2329`，死角观测量）。

**会不会让门/窗区域分类过期：会，但只是低概率的一次性 40px 假象，不是持续 A 的主因。**
- 若瓦片从 DIM/墙变成 VISIBLE（开门、墙被毁），其 `cornerReuseC=0、flags=0` 的旧值在复用命中时会让
  `f==VISIBLE && cLit==0 && (flags&240)==0` 成立 → `fillMemoryTile` 整瓦片涂 102/黑（`2368-2371`）——一帧 40px 黑块/暗块；
- 反过来旧 `cLit==4` 会让新近变暗的瓦片走 `fillLitTile`（`2363-2366`）跳过子格射线；
- 复用分支还会用旧 `flags` 回写 `seenSub`/`explorationBits`（`2322-2328`），可能误标/漏标“曾见”（显示层记忆）。
- **触发窗口很窄**：`fillFogCache` 只在 `needFov`（`2163`；`1100-1101`：眼移动 >4px、opac 变化、`frameCount%90==0`）或大场景 `sceneViewChanged`（`2118-2121`）时调用；
  复用要求“第二次调用在 4 帧内且眼点完全相同”，典型组合是“开门/关门/水变 + 90 帧兜底落在 4 帧内”或连续两次 opac 变化。
  大场景相机移动触发的同眼点复用是**安全**的（fov 本来就未变）。
- 角点缓存本身在 DIM 瓦片上从不更新，这是一个**语义空洞**：一旦状态迁移，旧值没有“无效”标记可依赖。

**证伪**：在离屏 harness 里记录 `reuseCorners/reusedTiles` 与“全量重算”的逐像素差；构造“同眼点 + 门 opac 变化 + 第 90 帧”序列，看是否出现一帧整瓦片 102/黑。

## 2. 问题 B（贴墙泄漏）逐问回答

### Q7 `castRay` 起点格：两个分支都没有扣起点 opac（已确定）

```
DDA 起点：c0x=floor(ex/40), c0y=floor(ey/40)        // 1905-1906
cached 分支：cell = c0x+c0y*w                        // 1964
  while(c1x!=tx || c1y!=ty){ 先步进 c1x/c1y/cell；再读 opacity[cell] }   // 1965-1983
非 cached 分支：同结构，先步进（2005-2014）再 tileOpac(getTile(c1x,c1y)) // 1999-2015
循环结束后：op = rayOpac[tx,ty] / tileOpac(target)；再扣一次并做 >=1 判定  // 2028-2037
```

- **起点格（眼点所在瓦片）的 opac 在两个分支都从未被读取/扣除**。唯一例外是“起点==目标”时，
  循环不执行，最后 `2028` 的一次目标采样会扣它一次。
- 因此：**眼点落在 `opac >= 1` 的瓦片内时，该瓦片对这束射线完全不存在**。
  对 1 瓦片厚的墙：射线从墙格内部直接进入墙后地板 → 后墙视野整片打开；
  对 2 瓦片及更厚的墙：下一步就撞到第二层墙格（`op>=1 → return -1`），只泄漏“眼点所在那一层”的背面（见 §2.3）。
- 若眼点恰在墙瓦片边界上：`floor()` 会把眼归到边界的一侧；从外侧瓦片出发时，第一步就进入墙格并扣除 → **不泄漏**；
  泄漏要求眼点**严格落在墙瓦片内部**。
- 补充：`cached` 的成立条件包含眼点/目标都在 `rayWidth/Height` 内（`1907-1909`）；眼点越界时走非 cached 的 `loc.getTile` 可能拿到越界格（健壮性问题，非泄漏主因）。

### Q9 除起点格外的其他泄漏通道（逐条结论）

1. **`computeFov` 的瓦片中心射线（`1808-1854`）与 `fov[]` 中心归类**：
   本身不产生“跳过起点格”以外的泄漏，但它是**放大器**：一旦眼点在墙格内，所有目标瓦片的中心射线都从墙内出发，
   `lit` 不再被该墙衰减 → 半径内整片被归为 `FOV_VISIBLE`（中心射线 lit 高）；随后 `fillLitTile` 把整瓦片涂成 alpha 0（`lDist1` 内）→
   “墙后视野”是**整墙后大片全亮**，不是只开一条缝。
2. **墙可见性传播（`1859-1894`）**：
   - 它只处理 `t.opac > 0` 的瓦片（`1869`），地板的 `opac<=0` 直接 `continue`，**不会反向点亮墙后地板**；
   - 它会把**0<opac<1 的门/窗瓦片**当作“可点亮的墙”提升为 `FOV_VISIBLE`（`1869` 只查 `opac>0`，`1882`）——这是 A 的第 4 条机制（见 §3/A-4），不是 B 的独立泄漏；
   - 眼点在墙格内时，它可能把这面“眼点墙”标 VISIBLE/explored、`br/litArr=1`（`1882-1888`）；`br/litArr` 是死字段，**对显示无影响**；`explored` 仅影响记忆。
   - 不会链式传播（邻居必须是 `opac<=0 && FOV_VISIBLE`，`1880`）。
3. **`fillFogCache` 四角分类与 `reuseCorners`（`2314-2362`）**：
   四角采样同样用 `castRay`，眼点在墙内时四角一起穿透，cLit 全为 4 → 直接进入 `fillLitTile`（见上）；
   `reuseCorners` 的过期是 Q6 的低概率一次性假象，**不具备持续泄漏能力**（沿用同一眼点的旧分类，而眼点若在墙内，新算也是漏的）。
4. **`MASK_LIT_A` / `currentSight`（单位遮罩）**：**没有独立于 Q7 的几何泄漏**，但有三处独立语义问题：
   - `recalcTile` 对任何 `lit>0.0001` 子格写 `currentSight`（`2421-2425`、`2456-2460`），
     门景 `logicalA=round((1-max(br,doorF))*255)=38 < 140=MASK_LIT_A` → **关门木门后的单位仍被标记为可见**（只是被 38 alpha 的雾压暗）；
   - `fillLitTile` 用 `logicalF=falloff` 且硬编码 0.35 写掩膜（`2504`、`2511`）→ 窗/栅格锥里的单位按“全可见”处理，即使窗的 0.2 衰减没进 `lit`；
   - `fillWallTile` 的快速路径按 `p00<MASK_LIT_A && fov!=NONE` 把整瓦片墙写进 `currentSight`（`2731-2733`）→ 贴墙单位/武器掩膜可能吃进墙格亮度；
     不过单位在 `visObjs[0..2]`、墙前景 `visFront` 在其上（`Grafon.as:191-206`；`Pt.as:23,40`），露馅程度取决于墙纹理覆盖与 zForm（待证）。
   - **注意**：这些是“掩膜口径”问题；在 `MASK_LIT_A=140`（`155`）下，雾 alpha <140（亮度 >0.451）才算“可见”，
     与显示 alpha 不是同一阈值。门景 38 远小于 140，所以门后单位永远算可见；这是设计还是漏洞，待拍板。
5. **`applyWorldVisual`/`fxCenterLit`/`refreshMask` 的中心点/单像素判定（约 4200-4300）**：
   - `fxCenterLit`（`4232-4242`）只取**注册点所在的一个子格像素**；`useSight` 时 `a!=0` 即视为可见；
     视野场未建立时直接返回 true（`4236`）；
   - `fxCenterDim`（`4220-4227`）按注册点所在**瓦片**是否 `FOV_DIM` 决定是否回退软遮罩；
   - `applyWorldVisual` 的 coverage 快路径先用角像素、再全像素判 `fullyLit/fullyDark`（`4286-4308`）；
   - 后果：弹体/粒子/手臂/长枪等“瞬态视觉”按**中心点**二值显示——中心在亮区/漏区时整个视觉原生直绘，
     即使尾迹/枪管跨进墙后；这是既有注释承认的局限（`4186-4195`）。
     它**不是玩家“墙后视野”的来源**（单位走包围盒+掩膜），但会在贴墙泄漏时让弹迹/粒子更明显。
6. **其它**：`applyUnitWeapons`/武器遮罩（`4000-4058`）跟随单位状态；`enforceTele` 用 `enemyState`（`4425-4482`）→ 如果单位因 `currentSight` 泄漏被判可见，念力抓取也会跟着放开（`blockInvisibleGrab` `887-932`）。这是 B 的**玩法级后果**，不是新通道。

### Q10 眼点在门/窗/水（0<opac<1）格内的亮度提升

**机制存在，已由代码确定**：起点格不扣 opac（Q7），所以当眼点所在瓦片 `opac=p`（0<p<1）时，
所有出射射线都少扣一次 `p`，等价于“把门/水当作不存在”。

- **门/窗格**：平时不可站立——关门/关窗时 `Box.setDoor(false)` 同时设 `phis` 与 `opac`（`Box.as:679-693`），碰撞盒进不去；
  开门的 `opac=0` 又无影响。只有“人还在门格时门被关上/被脚本塞进半透明格”才触发，**待证**（游戏是否会在关门时把玩家推出，未验证）。
- **可走的部分透明格：确定会触发**：
  - `tileop` 区域（`Area.as:186-190` 把整片 tile 的 `opac` 设为 0.2；`Rooms/rooms_nio.xml:1675` 是 31×13、opac=0.2、无 phis 的可走区域）；
  - 水（`opacWater` 0.2–0.75，`Location.as:167,386,418-420`；`castRay` 用 `tileOpac` 合并水，`2054-2062`）。
  以 `wopac=0.75` 为例：站在水里时出射射线本应 `lit=0.25`（若穿一层水）却算成 1；深水的“近身一圈”会明显偏亮；
  同时**目标格二次扣减**（A-5）让水格自身的 `lit` 变成 `1−2*0.75<0` → 0.05 → DIM → 门景 floor 0.85 → **38 的平顶**。
  于是同一片水会同时出现“眼周偏亮”和“目标水格 38 平顶”两种相反偏差——用户看到的是 40px 级水/门亮度补丁。
- 数值：门 opac=0.8 时眼点在其中会给出 `lit=1.0` 而非 `0.2`（5 倍）；窗 0.2 时 1.0 vs 0.8；水 0.75 时 1.0 vs 0.25（4 倍）。

## 4. ② 你可能漏掉的第三/第四种机制（相对 1-10 问）

- **M1（≈A-1，最关键）**：`fillLitTile` 的 **`cLit==4` 是“角点有任意光”而不是“四角全亮”**（`2345` 阈值 0.0001）。
  这使得门/窗锥体里几乎每个瓦片都命中快路径；快路径**完全不读 `lit`**。这不是“门景口径 vs 距离衰减”的二选一，
  而是**第三种**“无衰减口径”被悄悄用于门窗锥体。
- **M2（≈A-4）**：**墙可见性传播把 0<opac<1 的格子当墙点亮**（`1869` 只判 `>0`）。
  用户可能以为它只影响墙；实际上它把门/窗的 `fov` 从 DIM 改成 VISIBLE，直接改变渲染分支。
- **M3（≈A-5）**：**目标格 opac 二次扣减**（循环内一次 + `2028` 一次）。这是代码级 off-by-one，
  不是任何“口径”问题；它让门/窗/水的目标格亮度系统性偏低，并在阈值附近制造类别翻转。
- **M4（≈A-6）**：**墙/地板的亮度源在门景锥内互相矛盾**（原生 `visi` 扣过门;地板却抬到 doordim）。
  墙的“平滑”本质来自原生光场（1px/瓦片 + 0.1/帧缓动 + 40× 双线性 + RVWallSurface 32px 轮廓），
  而这个光场**也把门/窗的 opac 扣掉了**——于是墙认为门后很暗、地板认为门后很亮。这一点最容易被“只看 FOV 场”的审计漏掉。
- **M5**：**阈值浮点临界**：窗格自身 `lit=1−0.2−0.2=0.6000000000000001`，比 `Number("0.6")` 大 1 ulp；
  若再叠一层水/薄雾（多 0.2）就跌到 0.4 → 整个窗格从“VISIBLE/0”翻成“DIM/38”。一个 1 ulp 的差别对应 38 级 alpha，
  会让同一扇窗在不同房间/不同水层呈现不同补丁。**这是“补丁状”观感的直接放大器**。
- **M6**：**RVWallSurface 把 `opac<1` 当空气**（`heightAt` `295-302`）→ 门/窗瓦片没有暴露面、没有 32px 轮廓补偿、
  也没有 `wallEdgeLight` 的 2.5px 外侧采样（`2673-2689`）。即使射线场完全正确，门/窗边界也天生缺少墙那条“轮廓渐变”，
  这正是“墙看起来平滑、门窗不光滑”的**结构性**原因之一。
- **M7**：**`br`/`litArr` 是死字段**（写于 `1837-1838`/`1887-1888`，全文件无读）。任何“computeFov 已有连续亮度，
  显示层只是没用好”的假设都错——连续亮度根本不存在于数据流里；修 A 必须显式重建连续场。
- **M8**：**坐姿盒缩半**（`sitY=stayY/2=35`，`Unit.as:1043`；`sit()` 只换 scX/scY，`2510-2530`）。
  这是 B 最容易被忽略的触发条件：站着安全、坐下就漏。
- **M9**：**显示 alpha 与单位掩膜用两套下限**（生效 dim=0.6 vs 硬编码 0.35）：`2458`、`2511`、`2705`。
  它不直接造成“边界不平滑”，但会让同一块门窗区域的雾和单位显隐不同步（掩膜在雾还亮时就把单位判成不可见/可见）。
- **M10**：**大场景路径**：`sceneRefreshWallFieldFast`（`1677-1728`）与 `fillFogCache` 的 `sceneBounds` 裁剪（`2269`、`2295-2297`）——
  只有相机窗口+FOV 半径内的 tile 被重算，远处保留旧值；贴墙泄漏在窗口边缘可能有“留旧值”的额外时滞（`2144-2160` 的墙重绘、`2118-2121` 的 `sceneViewChanged`）。
  在 48×25 以上的大图（ContinuousScene 的 `sceneLarge`）才进入；小房间无此分支。**待证**其对 A/B 的贡献，但审计时应分开看。

在 E2 的模型里加状态机：帧 N 门开/关（opac 变化）→ 触发一次 `fillFogCache`；帧 N+1..N+4 构造“同眼点 + 第 90 帧兜底”的第二次调用；
断言复用命中时哪些瓦片被 `fillMemoryTile` 涂 102/黑（A-7）。**预期为少数帧**；若远超预期，才需要优先处理 A-7。

### E8（修法前的静态候选，不是实验）
最小、互相独立的候选修法（供后续会话评估，不在此实施）：
1. `castRay` 起点格扣一次 opac（或把眼点夹进碰撞盒/若眼点在 `opac>=1` 格则直接判定不可见）；
2. 删除 `2028-2037` 的终点二次采样（或只在“起点==目标”时扣）；
3. `fillLitTile` 改用 `litArr`/每子格 lit，不再丢衰减；
4. `1869` 改成 `opac >= 1`，别把 0<opac<1 的门/窗当墙点亮；
5. 统一门/窗/可见三种 floor 为“lit 驱动的连续场”，去掉 `doordim`/`dimF` 的平顶；
6. 让墙与地板共用同一个可见性/亮度源（或至少让 door 锥内的墙不做原生 visi 的二次扣减）；
7. 角点复用加“瓦片类变化即失效”的版本号。
（每条都能用 E1/E2 做单变量离屏对照，不需要游戏。）

### 7.4 一句话结论
**A**：不是“门/窗射线不够密”，而是 **DIM 平顶 + 门窗锥体的 `fillLitTile` 丢弃衰减 + 部分透明格被墙传播抬成 VISIBLE + 目标格二次扣减 + 墙/地两套亮度源** 叠加，在 40px 瓦片级分支切换下形成补丁；
**B**：`castRay` 不扣起点格是长期存在的“无害前提”，v0.34.3 把起点从盒内换到显示眼点后，坐/卧/飞等姿态下眼点可越出碰撞盒，前提被破坏 → 1 瓦片厚墙整面漏光。
