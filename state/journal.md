## 2026-08-29 v0.25.4：墙层零溢出单格写入——修边缘亮带与 v0.25.3 脏迹（离线像素模拟定位）

- 做了什么：用户报 v0.25.3 墙内阴影"反而更脏"。离线像素模拟（rv0253-wall-smudge-sim2.py，Python 复刻雾层/墙层双线性合成，输出 PNG 目检 + 剖面数值）定位：墙层 4 格写法里的 (2tx,·)/(·,2ty) 两格会向**西/北溢出 20px**——墙自身值被画进邻地板 = 亮带（亮墙溢出）与脏迹（暗墙溢出）的共同来源；而 (2tx+1,2ty+1) 一格在 -20,-20 位移下**恰好精确覆盖整瓦片、零溢出**。修复：墙层只写该格（wallKey 门控保留），v0.25.3 的边界雾层例外回退为全协调值。模拟四版对比（A v0.25.0/B v0.25.2/C v0.25.3/D 候选）：D 墙内干净度最优、地板无污渍、沿墙与穿墙阴影线位置与 B 一致。
- 关键决定/发现：位移半格下**奇数格 (2x+1,2y+1) 恰好等于整瓦片矩形**——这是"位移修偏移"与"零溢出"可以同时成立的关键几何事实；4 格写法的 W/N 溢出是 v0.25.2 亮带与 v0.25.3 脏迹的共同根因（溢出把墙值画进地板，亮墙=亮带、暗墙=脏影）。
- 遗留/下一步：待用户目检（边缘亮带消失、墙内干净、阴影位置保持中线侧）；模拟脚本与结论存 knowledge/experiments/rv0253-wall-smudge-sim2.py。

## 2026-08-27 v0.25.3：修复屏幕下/左边缘亮带——房间边界墙不用协调值

- 做了什么：用户确认 v0.25.2 墙内渲染大改善，但屏幕最下侧/最左侧出现 20px 亮带。根因：墙层位移半格后墙的 SE 半格露出雾层墙像素，内部墙=协调值（≈邻地板亮度=原版墙面受光，正确），但**房间边界墙**（tx=0/ty=0/最右列/最下行）外侧没有"墙外世界"，协调值却取内侧地板亮度 → 边界墙 SE 半格被照亮 = 屏幕边缘亮带（v0.25.0 无此问题，因当时雾层墙像素=自身值）。修复：边界墙的雾层像素直接用自身 aArr（亮墙整面亮、暗墙整面黑，与 v0.25.0 边缘行为一致），内部墙保持协调值。
- 关键决定/发现：协调值的适用前提是"四邻都在房间内"；边界墙的 SE 半格视觉上属于"墙外虚空"，应为自身明暗而非邻域均值。
- 遗留/下一步：待用户目检屏幕四边（不只下/左）；其余沿用清单。

## v0.24.7 优化：current/classic 性能（五处，两模式）

用户反馈：两种模式性能消耗仍略大；并询问能否让 GPU 帮忙渲染（结论见下）。

### 运行时验证先行：BlendMode.LIGHTEN 不可用于钳制

用 adl64 跑最小 AIR 测试程序（/tmp/rv_blendtest，结论存档）：
LIGHTEN 的 alpha 是 **source-over 合成**（166|50 → 183 而非逐通道 max 166），
RGB 也非逐通道 max（红|绿 → 黑）。→ 钳制无法换原生 draw，保留 vector 钳制。

### ① fov 重算节流（current/classic 共用）

快速跑动时 moved 每帧都超阈值 → fov 每帧重算（2-3ms 峰值帧 = 卡顿源）。
moved 触发的最小间隔 **3 帧**（重算频率降 ~3×，阴影边界滞后 ≤3 帧 ≈50ms，
由雾层模糊掩盖）；**墙破坏（hash 变化）不受限**（破坏墙即时更新视野）；
兜底 15→30 帧（站立时峰值减半）。

### ② 模糊+钳制拆帧（current）

fov 帧只做 fillFogCache+拷贝（峰值 ~3ms → ~1.7ms），模糊+钳制移到下一帧
（显示滞后 1 帧不可察觉）。门控：`!fogDirty && !fogBlurPending` 整帧跳过。

### ③ classic 雾层 30Hz 门控

applyVisionClassic + doorBoost 仅在**偶数帧或 fov 变化帧**跑全图循环。
站立时游戏 visi 冻结（循环零写入）→ 仅 30 帧兜底跑；移动时游戏 visi
自身 +0.1/帧平滑，30Hz 采样不可察觉；memCur 渐变速率减半同样不可察觉。

### ④ 武器/手臂扫描门控

武器扫描（每帧遍历整条 firstObj 对象链 + 每武器 enemyState）与 scanArms
改为 **fov 变化帧或每 3 帧**（敌人在边界移动时武器状态滞后 ≤3 帧 ≈50ms）。

### ⑤ classic 掩膜采样 classicRaw（零 raycast）

applyMask 的 classic 分支改为采样雾层 classicRaw（1px/瓦片，瓦片级缓存
复用）——与 current 的 fogCache 采样对称；掩膜与 classic 雾层**瓦片级
对齐**（门景/衰减环/记忆区/墙协调值，阈值同为 MASK_LIT_A=140）。raycast
路径仅剩兜底（对应缓存未就绪时）。

### GPU 渲染可行性（结论：不可行）

- 渲染模式（renderMode）由游戏 **application.xml 描述符**在启动时决定
  （cpu/direct/gpu），Loader 子域注入的模组**无法更改**；本游戏跑在
  direct 模式；
- 本模组的开销是 **CPU 侧计算**（raycast/像素循环/淡入），不是位图
  上屏——GPU 帮不上；显示层雾图与游戏原版 lightBmp 同为全屏覆盖，
  上屏成本与 vanilla 相当（模组隐藏了 visLight，不增负）；
- Stage3D 与显示列表混用需要 direct 模式且要重写雾渲染为着色器管线
  （纹理上传 + 全屏四边形），复杂度/风险远超收益，且游戏场景本身仍是
  软件渲染的显示列表。

### 验证

- 构建通过；ffdec 反编译确认五处优化完整（节流、拆帧、30Hz 门控、
  %3 扫描门控、classicRaw 采样分支）；BlendMode 行为经 adl64 真机验证。

**待用户游戏内确认**：快速跑动流畅度；classic 雾层 30Hz 下光环比对是否
可察觉；破坏墙后视野即时更新。

## v0.24.6 修复：①贴墙敌人武器误显 ②原版模式隐身敌人

### ① current/classic：记忆区贴墙敌人的武器错误显示

现象：视野扫过但未覆盖区域中贴着墙的敌人（本体隐藏正确），但手持武器
整把可见。

根因：贴墙敌人的 bbox 含**被邻域点亮规则标为 fov VISIBLE 的墙瓦片** →
enemyState=2 → 本体被 fogCache 掩膜正确裁掉（记忆区子格全暗）→ 武器走
`wpn.vis.mask = orec2.m2` 分支——**但武器 vis 没有 cacheAsBitmap**：位图
填充掩膜无 cache 时按矢量路径光栅化（整块矩形，v0.24.3 同款失败模式）
→ 武器全显。

修复：武器挂掩膜前 `wpn.vis.cacheAsBitmap = true`；`setWeaponVis` 摘掩膜
同时关缓存。

### ② 原版（vanilla）模式偶尔隐身敌人

现象：F12/F11 切到原版后，部分敌人隐身；切回 current/classic 又能看见。

根因（两类残留）：
1. **hideUnit 残留**：切模式后 hideEnemies 停止运行，此前在暗处被隐藏的
   敌人 `vis.visible=false` 永远不恢复（vanilla 没有任何恢复路径）；
2. **过期掩膜残留**：resetRoom 不清 unitVis——旧掩膜（u.vis.mask + 显示
   树里的掩膜 Shape）继续裁剪单位，玩家移动时敌人时隐时现（"有时"）。

修复：新增 `restoreAll(w,loc)`，在透传分支（vanilla/总开关关/安全基地/
黑暗关）每帧调用——①摘除全部掩膜（含显示树残留）；②恢复被隐藏单位
（showUnit：vis/prior/hpbar）；③恢复武器（visible+摘 mask+关 cache）；
④恢复显示树隐藏的附属对象（狮鹫手臂）。门控：三字典全空时零开销。

### 验证

## v0.17.4 变更：墙四分格映射（去波痕）+ classic v4 雾场自渲染（去 40px 阶梯）

用户反馈：① current 墙内出现锯齿波痕 ② classic 记忆区边界修复几乎无效果。

### ① current 墙：四分格映射取代半平面面向规则

- **波痕根因**：半平面"面向"规则按瓦片取 bestBr（逐瓦片亮度马赛克）+
  二值面向边界 → 墙面上出现波状色带。
- **方案**：复刻原版掩膜半格错位的确切机制——**四分格映射**：TL=自身 /

  对应瓦片为墙/暗区时按历史（曾见→166，否则→黑）。墙亮厚度=原版一致
  （约半格到 3/4 格）。

### ② classic v4：雾场自渲染（复刻游戏 visi + 记忆暗化 + 隐藏游戏掩膜）

- **修复无效根因（离线模拟复现）**：v3 覆盖层是半透明的（166/255），游戏
  lightBmp 的 40px visi 场透过覆盖层渗出——光缘环边缘 visi≈0.07（近黑 236）
  与记忆区 166 形成"近黑↔亮带"的 40px 阶梯；覆盖层无法抹平游戏掩膜。
- **方案（v4）**：classic 改为与 current 同管线的**雾场自渲染**，隐藏游戏
  visLight：
  - 可见区：alpha = (1 - **max(visi, dimF)**)×255——游戏 visi 原样复刻
    （40px 原版亮度、淡入节奏）+ **记忆暗色下限**：光缘环衰减终点=166，

    曾见→166，否则→255；
  - 边界全部 5px 子格粒度；门景 doordim 仍经 doorBoost 写 visi 生效。
- 逻辑语义不变（checkPort/Sats 走游戏 visi；敌人隐藏/念力规则不变）。

## v0.17.3 变更：可见墙点亮（原版半格错位效果）+ classic 记忆区边界子格化

用户反馈：① current 应跟进原版"墙壁内部一定厚度渲染为亮区"；② classic
记忆区边界仍有"墙壁单位"（40px）锯齿。

### ① current：可见墙按邻域亮度点亮（fillWallTile）

- **背景**：原版的亮墙是掩膜半格错位造成的——边界处掩膜单元覆盖"半个亮地板+
  半个墙"，墙的内半侧显示邻域亮度（"墙内一定厚度为亮区"）。本模组瓦片对齐
  雾层此前把可见墙渲染成均匀记忆暗色。
- **方案**：fov==VISIBLE 的实心墙瓦片（opac≥1）逐子格判定"面向"——子格落在
  朝向某个可见非阻挡邻域的半个瓦片内 → 按邻域最大亮度点亮（亮度随光缘衰减，
  记入曾见历史）；背侧子格按历史（曾见→记忆暗色，否则→黑）。记忆区墙改为
  按子格历史填充（内半侧 166/外半侧黑）。
- 代价：每 FOV 重算对可见墙瓦片做 8 邻域扫描 + 64 子格写入（墙瓦片数量少，

### ② classic：记忆区边界全部子格化

- **根因**：上一版覆盖层对"已探索"瓦片整体填 166（40px 块），其边缘与光缘环/

  - 光缘环/前沿带瓦片（4 角有光）做完整 8×8 子格 raycast，其余整块填充——
    两条边界都变成 5px 粒度 + 模糊渐变。markSeenPass 已合并进覆盖层。
- 代价：classic 移动时增加约 5-20k 条子格 raycast/帧（光缘+前沿带）。

## v0.17.1 变更：三模式重构（性能 / 原版恢复 / 仿原版对齐）

用户三项反馈：① current 性能 ② vanilla 模式不对劲 ③ classic 与原版区别大。

### ① current：性能优化（fogCache + 4 角采样分类）

- **原开销**：每次 FOV 重算对全部已探索瓦片做 64 次 raycast（~7.7 万条/帧）。
- **现方案**：
  - 最终 alpha 场缓存到 `fogCache`（BitmapData），**只在 FOV 重算时更新**；
  - 重算时每瓦片先做 **4 角采样**分类：
    - 全暗（fov NONE 且 4 角全暗）→ 整块 fillRect 记忆暗色（零 raycast）；
    - 全亮（fov VISIBLE 且 4 角全亮）→ 无 raycast，只算逐子格距离衰减
      （亮度 = max(falloff, dim)，保持瓦片内渐变）；
    - FOV_DIM / 明暗混合（阴影线所在瓦片）→ 完整 8×8 raycast（线状阴影
      仍由这些瓦片产生，视觉不变）；
  - 每帧仅 `copyPixels`（收敛后）或淡入缩放（进房后 ~10 帧）+ blur——
    **站立时零 raycast**；移动时约 4×1200 角采样 + 边界瓦片 64 格
    （预计 ~1.5-2.5 万条，为原来的 1/3~1/5）。
- 视觉语义不变：全亮瓦片近似"角点全亮即内部全亮"（凹形阴影偶发近似，
  模糊掩盖）；未探索恒全黑、记忆区均匀、光缘渐变保留。

### ② vanilla（原版）：纯透传

- **根因**：`resetRoom` 无条件清空全部 `visi/t_visi` 并隐藏 visLight——
  模式切换（F11/F12）后已探索区被清零且游戏 lighting() 只在移动/触发时
  重算，记忆区永久变黑；与干净备份的原版行为不符。
- **修复**：透传模式（vanilla / 总开关关 / 游戏黑暗关 / 安全基地）下**完全不碰**
  `tile.visi/t_visi/lightBmp`，只隐藏模组雾层；进入透传瞬间调 `grafon.setLight()`
  把掩膜恢复到当前 visi（残留旧值问题），`visLight.visible` 按游戏规则
  `loc.black && w.black`。原版行为（含半格错位掩膜/硬边/已探索常亮）原样恢复。

### ③ classic（仿原版）：原版渲染 + 记忆区暗色覆盖层

- **根因**：旧 classic 是模组自绘（瓦片中心距离衰减 + 模糊 + 钳制）——亮度公式、
  光源点、掩膜对齐（半格错位）、淡入节奏都与原版不同，"仿原版"仍差距明显。
- **修复**：光照本体（亮度渐变/光缘/瓦片线/淡入/掩膜半格错位）**完全由游戏原生
  lightBmp 提供**（与 vanilla 一致，`visLight.visible` 恢复，`tile.visi` 交还游戏
  按原版 lighting() 管理）；模组只在 visLight 之上叠加暗化层：**已探索且当前
  fov==NONE → 记忆暗色 dimA**，其余透明。模糊 + 单侧钳制保留（记忆区均匀、
  可见侧柔和半影去颗粒感）。
- 连带：checkPort/Sats/PipBuck 地图等游戏逻辑回到原版语义；敌人隐藏/念力规则
  不变。
- 已知小差异（接受）：模组 fov 光源点/半径测量与原版略有不同（~半格），
  光缘最外圈 ~12-28px 的过渡位置有微小偏移。

## v0.13 修复（重要：渲染公式平方项 bug）

- **渐变消失/classic 不对的根因**：v0.9 起渲染公式为 `alpha = 255×(1 - cur×target)`，
  而 cur 收敛到的是**亮度目标值**（0..1）——平方项把中间亮度压向全黑
  （亮度 0.5 → alpha 191 而非 127；记忆区 0.35 → 224 而非 166），渐变被压缩进
  最黑的 25%，观感"没有渐变"。两种雾模式都中招。
- 修复：**线性公式**——非视野瓦片 `alpha = 255×(1-cur)`；视野内子格
  `alpha = 255×(1 - cur×(子格亮度/瓦片目标亮度))`，收敛时恰为
  `255×(1-子格亮度)`。
- **模式可见性**：
  - F12 切换时屏幕右上角显示 3 秒提示"视野渲染模式: 原版/经典(v0.7.2)/当前"；
  - F10 调试面板第一行常显 `mode=...`；
  - PipBuck 选项页面板照常显示。

## v0.11 修复：亮边 + 厚墙内部显示过多（双线性平滑渗色）

- **根因**：v0.10 开启的位图双线性平滑会**跨状态边界双向渗色**——记忆区/未探索
  瓦片靠近亮墙的边被渗亮（亮边），厚墙内部被亮面渗入（显示过多）。
- **修复**：
  - 关闭位图平滑；
  - 渐变改由**雾场自身 10px 子格采样**提供：视野内瓦片逐子格计算
    `lit × 距离衰减`（连续亮度场）——光缘渐变保留且更细；
  - 记忆区/未探索每瓦片均匀值——状态边界干脆，无跨边界渗色。

## v0.10 变更：让渐变真正可见（去除灰底）

- **根因**：v0.9 给"探索过"的瓦片设了记忆暗色下限（max(br, 0.35)）——光缘环
  衰减的终点是 166 的灰底而非全黑，渐变被灰底吃掉，观感"没有渐变"。
- **修复**：
  - 视野内（FOV_VISIBLE）目标 = 连续亮度 br **直接使用**（无下限）——光缘环
    从全亮连续衰减到**全黑**（原版高对比渐变，与未探索黑域无缝衔接）；
  - 记忆暗色只用于"部分透光（门/水后）"和"扫过未覆盖"两类瓦片；
  - 雾图 Bitmap 开启**双线性平滑**——相邻瓦片亮度值连续插值，渐变呈连续场
    （比原版 40px 硬块更平滑的呈现）。
- 时序渐变（0.1/帧双向）保留。

## v0.9 变更：实现原版式渐变（连续亮度 + 时序呼吸）

- **连续亮度（原版 lighting 公式）**：每瓦片 `br = LOS 亮度(1-累计遮光) ×
  距离衰减(lDist1→lDist2)`——原版"大量渐变"的本体。渲染亮度不再三态二值：
  - 视野内：亮度连续（部分透光的门/水/栅格产生逐级渐变，光缘环连续衰减）；
  - 探索过但不可见：亮度下限 = 记忆暗色（dim）；
  - 未探索：0（全黑）。
  - 目标亮度 = max(br, dim)（探索过的瓦片）；光缘环渐变直接融入记忆暗色，
    交界处无硬台阶。
- **时序渐变（原版 updVisi 节奏）**：每瓦片亮度以 0.1/帧向目标渐变（双向）——
  移动时光照呈呼吸式扩散/收缩，而非瞬间切换（fadestep 默认改回 0.1）。
- 边界呈现：每瓦片一个值（原版瓦片量化），无空间滤波——渐变来自**光源模型的
  连续性**（亮度场），与原版机制一致。
- 备选回退（若此观感仍不理想）：覆盖↔扫过交界线改回 v0.7.2 的观感（子格
  ramp + 半影）——只影响 applyVision 渲染段，随时可切换。

## v0.8 变更：雾层回归原版式渲染（干脆瓦片线，去颗粒感）

- **方向修正**（回应"原版线状效果"）：放弃子格混合/半影等空间平滑手段——它们
  制造的是颗粒感而非原版观感。原版的边界本来就是**干脆的瓦片线**（每瓦片一个
  亮度值、掩膜 40px 硬块），其"线状"效果来自高对比的干净边缘 + 距离衰减光缘。
- 现实现：
  - 雾图回到 **1 像素/瓦片、无空间模糊、无半影、无钳制**（Bitmap smoothing=false，
    与原版掩膜一致的 40px 硬块）；
  - **距离衰减光缘保留**（lDist1→lDist2 线性 ramp）——这是原版光照平滑感的
    唯一来源；
  - 三态每瓦片一个值：视野内=ramp(distance)，扫过未覆盖=记忆暗色(dim)，
    未扫过=全黑。
  - 边界观感：覆盖↔未覆盖为原版式光缘环；扫过↔未扫过为干脆的高对比瓦片线
    （"线状"）；无颗粒、无块状感糊边。
- 性能大幅下降（每脏帧仅 1200 次 fillRect，无模糊/无子格 LOS）。
- 敌人掩膜保持 10px 子格裁剪（与 v0.6.3 起一致）。

## v0.7.2 变更：未探索边界半影（去颗粒感）

- 上一版钳制把可见侧也保持"洁净"，导致阴影边界与未探索边界是 0↔255 硬跳变
  （10px 块状颗粒感）。改为**单侧半影**：
  - 未探索（>=254）仍保持全黑（无光晕渗出）；
  - 记忆区暗色（dimA±4）保持均匀（无亮带）；

    （FOG_BLUR 1.5→2.0），未探索边界不再块状。
- 半影只落在可见侧：暗区纯度、记忆区均匀性、墙体亮面均不受影响。

## v0.7.1 排查结论与修复：阶梯状明暗交界（"墙的单位"= 瓦片 40px）

- **排查确认（用户观察正确）**：墙厚是 Tile 尺寸（40px）的整数倍；而雾值此前
  是**每瓦片一个常量**——距离衰减环以 40px 为步长同心阶梯，阴影边界沿墙呈
  40px 阶梯（瓦片级 LOS 的固有量化），与"墙的单位"完全一致。
- **修复（雾层渲染重构为子格级 10px）**：
  1. 距离衰减按**每个 10px 子格**独立计算（光缘环平滑到 10px 粒度）；
  2. 可见区与不可见区相邻的**边界瓦片**：对其每个子格中心做**子格级 LOS 光线
     判定**——墙体阴影边界也平滑到 10px 粒度（阴影内子格按 暗/记忆 取值）；
  3. 淡入进度（visCur 0→1）与亮度分离：三态亮度全部编码在子格目标值里，
     淡入只做进房/开关时的整体渐入，不再参与稳态亮度。
- 掩膜（敌人裁剪）此前已是子格级，与雾层一致。
- 性能：移动期间每帧约 1.9 万子格写 + 边界子格约数千条短光线（数毫秒），
  由脏标记门控；F10 面板可看帧耗时。

## v0.7 变更：距离衰减光缘（原版风格平滑边界）

## v0.5.1 修复：白色色块 + 暗处可见（掩膜生命周期硬伤）
