## 1. 调查结论（源码级机制）

### 1.1 症状一机制链：跨界弹体的逐帧软遮罩重建（v0.34.3 语义回归）

v0.34.3 为修复"弹头进暗区后整条亮处尾迹提前消失"，把三种弹体（Bullet/SmartBullet/PhisBullet）从 v0.33.16 的中心点二值快速路径移回**全几何空间软遮罩**，dispatch 见 `RealisticVisionMod.as:3965-3973`（`applyWorldVisual(obj.vis, kind==2)`，dynamicBounds=true）；部署报告当时已自述"恢复弹体软遮罩及移动眼部重算可能增加密集射击时的开销"。fx_vision_quality=0 现在只让 Part（火花/弹壳/烟雾）保留二值快速路径。

每弹每帧的实际成本分层（`applyWorldVisual:4101-4235`）：

1. **所有弹体（无论明暗）**：dynamicBounds=true 绕过外框缓存（:4114）→ 每弹每帧 `getBounds`；弹体移动跨瓦片 → `worldMasks` 新 key（:4134-4136）→ 每弹每 1-2 帧新建 raster：m2d `BitmapData` 分配 + currentSight `copyPixels` + 均匀性分类（`refreshMask:3416-3513`）。
2. **全亮/全暗弹体**：在均匀分类处早退（:3509-3513），不模糊不建 Shape——**开阔地（无边界）开火只付小成本**，与用户"无边界不卡顿"的收紧观察一致。
3. **跨界弹体（边界穿过弹体包围盒）**：进入完整路径——m2e 分配 + `applyFilter(maskBlurCurrent)` CPU 高斯模糊 + `finishCurrentMask`（:3542-3554）+ Shape graphics 重建（:4216-4229）+ `shape.cacheAsBitmap=true`（:4231）+ `visual.cacheAsBitmap=true`（:4232-4233）→ Flash 渲染段对每颗跨界弹体做**双重栅格化 + 逐像素 alpha 合成**。这正是 [framerate-liberation-plan](framerate-liberation-plan.md) 已证的"动态 cacheAsBitmap 遮罩死穴"。

**量化旁证**：v0.33.16 把特效移出该路径时整帧 −3.2%~−9.3%、RV 调用 −34%~−64%、固定 108ms 尖峰清除；v0.34.2 激光例外回软遮罩时因"每炮塔在场仅 1-2 发"判定开销可忽略——普通枪弹（LMG 在场弹体十倍级）在**边界穿过弹道**时才触发完整路径，与"有正在渲染的阴影边界时开火才卡"精确吻合。

**放大器（已证实，2026-11-03）**：交战中玩家承受命中产生小幅持续位移（击退/踉跄），眼点随身体移动，每 ≥4px 触发 `computeFov`+`fovVersion++`（:1067-1099）→ 同帧级联：fillFogCache 全量射线（实测 ≈11.9ms/次）、雾显示重绘、`updateWallSurface` 重建、`sightClasses` 重分配（:3258-3262）、全部 state=2 敌人掩膜与活动 raster 失效。重载相位 computeFov 246~343 次/450 帧（每 1.3~1.8 帧一次）；轻载相位仅 6~27 次。该级联是重载相位 RV 成本的绝对主导（≈13ms/帧 vs 弹体路径 ≈0.9ms/帧），**并同时解释症状二**（敌人命中→位移→级联，几何依赖决定复现性）。证据见 [实验报告](../knowledge/experiments/2026-11-03-raster-grid.md)。

### 1.2 症状二候选机制（敌人活动卡顿，敌数无关、不稳定复现）

按可能性排序：

RV 侧（与本模组相关）：
- **敌方弹体与玩家弹体同路径**（:3957-3973 无差别处理对象链上所有 Bullet）——敌人开火=小规模版症状一。卡顿取决于**弹道是否跨过阴影边界**（几何依赖）而非敌人数，且 AI 开火时机随机 → 吻合"敌数无关+不稳定复现"。
- **敌人跨边界移动**：state=2（部分可见）时 bb 瓦片签名变化 → `applyMask`/`refreshMask` 全量重建（分配+copyPixels+blur+finishCurrentMask+Shape，:3383-3561、:3791-3795）；敌人在边界附近走动时每跨一次瓦片付一次全量。
- fadeCount 渐入渐出的 alpha 写入（:3769-3807）使单位 vis 缓存失效；enemyState 每帧 bbox 瓦片分类（:3232-3348，瓦片分类有 sightClasses 缓存，成本中等）。

非 RV 侧（不可全归 RV，本工作区已有实证）：
- D57/156/168 多轮实测：**低执行量长帧在 RV 关闭窗也出现**（156：211ms 帧的 107.6ms 后段仅 15.6ms CPU≈0.145 核；168：RV off 窗 205ms 帧后段 177ms）——存在呈现/驱动/运行库等待类长帧，与"不稳定复现"特征一致。
- 敌人活动同步推高原生 AI/寻路/动画与 GC 压力（D57 见内存骤降伴随长帧）。

→ **结论：症状二必须先归因再优化——若长帧落在非 RV 段，RV 侧任何优化都无法消除。**

## 2. P0 归因实验（先证实机制，再动手；可直接执行）

工具：fire-exhaustive 链（`build/fire-exhaustive`）+ agent-debug（benchmark profile、共享登记）。纪律沿 KB-000123 r5：同进程 A/B、正反序、逐窗方向一致、同字节 A/A 控制（A/A 假差曾达 12.3%，不能只看合并均值）。

1. **诊断构建**（独立测试包，不部署）：每帧计数器——跨界弹体数、弹体 raster 新建数、弹体完整遮罩重建数（blur 路径）、state=2 敌人数、敌人掩膜重建数、needFov 原因分解（eyeMoved/opacity/struct/90 帧兜底；`atFovM/atFovH/atFovF` 已有）以及 RV 内部分段耗时（computeFov/applyVision/updateWallSurface/hideEnemies/applyWorldVisuals）。
2. **场景矩阵**（每格固定+移动、正反序）：
   | 格 | 边界 | 开火 | 敌人 |
   |---|---|---|---|
   | A | 无（开阔地） | 玩家开/停 | 0 |
   | B | 在屏 | 玩家开/停 | 0 |
   | C | 在屏 | 停 | 1 敌活动 / 6 敌活动，敌人开火与不开火分离 |
   | D | 在屏 | 同 C | 同 C 但 RV off（对照非 RV 长帧） |
3. **判据**：
   - 症状一成立 = B-开火窗的跨界弹体重建计数与 >100ms 帧同帧相关，A 窗显著更低；
   - 眼点抖动假设成立 = 同站位持续开火时 atFovM 显著高于停火；
   - 症状二归因 = 长帧对齐敌人开火/跨界移动事件 → RV 侧（走 §3 C5/C1）；在 D 格（RV off）也复现 → 非 RV 段（走 §4）。
4. **非 RV 长帧等待源采样**（Scout/WCT 可行性，普查报告已提出未做）：结果**单独记录，不混入 RV 收益**（用户 2026-11-01 指示：非 RV 研究分开）。

## 3. P1 优化候选（按证据强度与风险排序）

### C1 弹体 raster 键量化到粗网格【无损，首选 → 已执行，未部署】
**2026-11-02/03 执行结果**（[报告](../knowledge/experiments/2026-11-03-raster-grid.md)）：WORLD_RASTER_CELL=2 实现；同进程双版本严格像素等价 623 项全过（含持续绑定/位移扫掠/直接调用）+ 栅格复用阳性对照（12→6）。性能三正序轮轻载相位 rv −10%~−40%，但重载相位（战斗位移致 FOV 每帧失效）refreshMask 单位成本 +22%、调用数不降、rv +1.7~+3.2ms——**方向随场景相位翻转，不满足稳定收益纪律，不部署**。FOV 级联摊薄后可重估。

原始设计（供后续重试参考）：
把 `worldMasks` 的 key 从精确瓦片区间量化为对齐 2×2（或 4×4）瓦片的粗网格区间：弹体在粗格内移动时命中既有 raster——`refreshMask` 的 `lastFov==fovVersion && lastBb==sig` 早退直接生效，消除逐帧 BitmapData 分配+copyPixels+分类；粗格内 raster 输入不变 → `inputRevision` 不变 → Shape 不重建。
- 语义：无损（同一视野场同一采样，仅外框取整扩大）；需按 v0.34.3 checks-07 的 771 项风格做跨界弹迹图像对照。
- 边界：粗格 raster 的均匀分类扫描像素变多（2×2 网格约 ×4），换取每帧零分配；`drawClip` 仍按弹体实际外框逐帧计算（:4203-4211），**部分弹体的 Shape drawRect 逐帧重绘仍在**——由 C2 解决。
- 预期：消除症状一/症状二 RV 侧的"逐帧分配与小图处理"部分。

### C2 跨界弹体重建节流【微画质取舍，需拍板】
跨界弹体的完整重建（Shape 重绘+缓存切换）限频：每弹体每 k 帧（k=2~3）或每帧全局预算 M 个、超额顺延；全亮/全暗早退不受限。
- 画质：跨界瞬间遮罩更新滞后 ≤2-3 帧（约 50ms），远小于 v0.33.16 完全二值化的取舍（用户当时已接受更大取舍）；
- 与 v0.34.3 修复动机正交：遮罩仍按弹体全几何，仅降频，弹迹不提前消失。

### C3 跨界弹体遮罩降模糊【微画质取舍，需拍板】
仅对 kind==2 的 worldRaster 把 maskBlurCurrent 降半或归零（省 `applyFilter`）：弹体是最高速对象，羽化在运动中不可察觉。与 C1/C2 正交可叠加。

### C4 战斗位移 FOV 级联摊薄【已升为第一优先（2026-11-03 实证）】
归因更新：稳态射击不动眼点（diag-02 逐帧采样零位移）；级联由**承受命中的真实位移**（击退/踉跄）驱动，每 ≥4px 全量级联（fillFogCache ≈11.9ms + 雾重绘 + 墙体重建 + 全遮罩失效）。原"射击动画迟滞"方案作废（无抖动可滤）。新候选：
- 方案 a（需拍板）：**小位移分档重算**——Δeye 小于阈值上界（如 8px）的战斗位移按 2~3 帧节奏重算 FOV（角点/栅格跨帧失效减少）；眼点跟随语义的额外滞后上限 ~2px/帧，与既有 4px 阈值同量级，但严格说非无损，需用户接受；
- 方案 b（研究项）：**fillFogCache 小 Δ 增量化/区域受限重算**——远场可见性对小 Δeye 大多不变；D51 射线空隙同类尝试无稳定整帧收益、v0.34.3 收紧跨起点角点复用（旧墙角阴影回归风险），须新设计独立验证；
- 方案 c（探索）：击退/踉跄动画期间位移对视野场的影响本身近似平移——平移复用旧场+边缘补算的等价性需严格图像对照（历史缩放/裁切类均有像素反例，谨慎）。
该方向同时覆盖症状一与症状二的公共主因，优先级高于 C2/C3/C5。

### C5 敌人掩膜与弹体 raster 缓存统一【结构性，后置】
state=2 敌人 `applyMask` 用 unitVis 私有 m2d/m2e，与 worldMasks 是两套分配；统一到 C1 的粗网格 raster 池后，敌人跨瓦片移动可命中邻近 raster 免全量重建。收益对象=症状二的 RV 侧部分；但敌人遮罩语义（血条 m3、fadeCount、maskRevision 共享给武器）复杂，放后位，待 C1 落地验证后再评估。

### 明确不做（普查 76+ 轮已否决，不重复）
空遮罩/合罩结构变化（69 合罩 1600 像素反例）、直接 Bitmap 替代 Shape（74/76/131 缩放反例）、批量预绘（135/136 整帧更慢）、贴图上传门控与固定字段记录（62-66 不稳定）、池化/临时图交换（04-08/15 无整帧收益）、cacheAsBitmap 语义关闭（113/127 全不同）。任何新候选必须先过 P0 机制归因，不凭局部计数减少宣称收益。

## 5. 验证纪律（每候选必须）

1. **图像**：跨界弹迹语义沿 v0.34.3 checks-07（771 项）风格——弹头/尾迹分侧像素计数、60 步持续绑定、同坐标自身几何变化；敌人侧加门区（FOV_DIM）回退语义检查（v0.34.1）。
2. **性能**：fire-exhaustive 同进程 A/B 正反序 + 逐窗方向一致 + 同字节 A/A 控制（KB-000123 r5）；只按同场景同输入比较，不跨轮拼接绝对值。
3. **场景覆盖**：边界在屏/无界 × 开火/停火 × 敌 0/1/6；移动+固定两种站位。
4. **部署**：走 remains-release-gate；config 新键只增不改（字节级追加），备份与回退路径照旧；`vision_quality_preset=2` 保持总回退能力。

## 7. 决策点（需用户拍板；2026-11-03 更新）

1. **C4-a 小位移分档重算**是否接受（战斗位移下视野重算最多滞后 2~3 帧/~几 px，换来重载相位每帧 ~13ms 级联的显著摊薄）——当前推荐首选；
2. C4-b fillFogCache 增量化作为研究项是否立项（工作量与失败风险均高，D51 同类前科）；
3. C2/C3 的弹体画质取舍是否仍要（级联摊薄前预计收益被淹没，建议延后）；
4. 非 RV 长帧方向（§4）是否单独立项。

## 8. 与既有结论的关系

- 遵守 2026-11-01 用户指示：RV 本体评估不加载光与暗，非 RV 结果分开记录；
- 尊重普查会话 76+ 轮否决清单与 KB-000123 的计时纪律；
