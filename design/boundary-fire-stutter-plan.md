## 1. 当前判断

用户观察保留为两个待验证的问题：①存在正在渲染的阴影边界时，开火容易卡顿；②敌人单独活动也可能卡顿，单个敌人即可出现，尚不能稳定复现。不能把“似乎相关”升级成“只有该条件才会卡”，也不能据此断言成本与敌人数无关。

源码确认了两条优先调查的路径：**弹体所在区域混合明暗时的软遮罩处理**，以及**眼点改变引起的视野场、雾层和墙体刷新**。前者解释为什么弹道靠近边界可能变贵；后者在既有重载夹具中占主要 RV 执行时间。尚无严格对照证明哪条解释了用户的现场症状；敌人自主活动的原因尤其未定。

推荐顺序：**纠正测试配置和计数口径 → 最小因果对照 → 对主要成本做保真优化 → 再决定是否提供画质选项**。原方案直接推荐延迟视野刷新，依据不足，现予撤回。

## 2. 证据与旧结论修正

C1 粗格缓存的 **623 项图像检查及 12→6 复用阳性**仍成立；性能没有可靠采用依据，继续不部署。但不能把混杂场景的差值全部归给粗格算法，或把“受击导致两种症状”写成确定根因。diag-02 稳态眼点静止仅排除该夹具中的射击眼点抖动，不推广到全部武器/姿态。

实际设置优先读取 Local Store 的 `RealisticVision_config.txt`，缺少才用安装模板（554–559）。调查阶段相关只读命令被保护钩子拦截，精确升级仍未通过，未绕过；当时用户实际设置尚未核验。后续实施阶段单独只读查询成功：current、4 子格、motionstep=4、dim≈0.6、doordim≈0.85，测试正确调用 loadConfig 并派生滤镜；保存的 enabled=0 保留，只在隔离实例开启。经验查询仍有不可读来源，未宣称检索穷尽。

## 3. 机制与可证伪假设

### H1：弹体遮罩与显示合成

弹体每次重新取显示外框，再按瓦片范围查 `worldMasks`（4108–4145）。范围外另补左右 2、上 3、下 1 瓦片的滤镜支持区，所以弹体视觉上未碰边界也可能进入混合区。新键、视野代次或输入变化可能引起取样、模糊和遮罩重绑（3390–3592、4220–4241）；均匀区可早退。屏幕其他位置有边界，不等于该弹体走了昂贵路径。

**预测**：固定真实眼点、无敌人和结构变化时，靠近/穿过边界的开火窗增加实际混合处理或呈现耗时；若“边界在屏但远离弹道”也卡，应追查全局场刷新或其他显示成本。两个 `cacheAsBitmap` 属性不能直接证明 GPU 双重栅格化次数。

### H2：眼点/遮挡变化引起全场更新

`computeFov → applyVision(fillFogCache、雾滤镜) → updateWallSurface → hideEnemies` 是实际调用链（1021–1116、2003–2161）。新代次使局部遮罩重新检查输入，输入相同的部分仍可复用，不等于全部完整重建。

**预测**：重放相同眼点轨迹，无开火也有相应重算成本；锁定眼点而保留弹体活动，该成本应减少。命中、身体/显示眼点和结构变化必须在同一帧记录，才能归因受击；还需区分落地、挤碰、主动移动和驱动复位。

### H3：敌人跨界与动画

`hideEnemies` 每帧分类，部分可见时走 `applyMask`，范围或输入变化后更新；武器/手臂另处理，从暗到亮还会渐入（3239、3369、3714、3861）。一个敌人的跨界、开火或动画就可能增加成本。

**预测**：玩家/眼点固定、敌人不开火时，跨界比全亮区活动更贵，并与部分可见状态、外框和实际重建同步。若同场景 RV 关闭仍发生，按原生 AI/动画或帧间等待记录，不能全部归给 RV。

### H4：RV 之外的长帧

既有普查记录过 RV 关闭仍有长帧。渲染事件之后的间隔包含绘制、调度和其他工作，不能直接叫 GPU 等待。先留同场景 RV off 对照；低 RV 耗时慢帧重复出现后再进入独立宿主调查，不在本轮扩成驱动/系统优化。

## 4. P0：最小归因轮

### P0-a 使夹具代表正式运行

- 冻结当前 SWF、对应源码和实际配置；通过同一配置解析/派生初始化路径启动，打印 mode、fogSub、maskBlur、dim、soft、motionstep、preset、stage 帧率和缩放。先解决 8/4 子格偏差，不能只改字段而漏掉滤镜/矩阵。
- 固定地图、出生点、相机、探索历史和完整单位清单；不把新增敌人数当总数。保留正常菜单退出、原生输入及动画，只控制本实验所需行为。
- 关闭 LightAndDarkness，确认实际加载记录，依赖一致。通过 ModLoader 共享登记、独立存储、静音后台实例执行，不操作玩家进程/存档/正式名单；按 benchmark 环境判断能否计性能。
- A/A 两槽复制同一份编译产物并核对哈希。函数计数、位置、事件、计时都在预热结束时一起清零；归因插桩与性能验收分开。

### P0-b 按顺序对照，不先跑全排列

| 顺序 | 控制场景 | 要回答的问题 |
|---|---|---|
| S0 | 0 敌，无边界覆盖弹体/支持区；停火→开火 | 开火基础成本与波动 |
| S1 | 边界在屏但不接触弹体支持区；停火→开火，眼点固定 | 仅有边界在屏是否足够 |
| S2 | 保持场景、眼点、武器和发射数，改变弹道使其经过边界 | 是否跟随混合遮罩数量/面积增长 |
| S3 | 玩家停火、1 敌不开火；全亮区活动→边界附近活动，眼点固定 | 敌人自身活动是否足够；必须命中部分可见分支 |
| S4 | 1 敌原生开火，分别阻止命中和允许命中，记录眼点轨迹 | 区分敌方弹体与受击位移，记录隔离手段副作用 |
| S5 | 对已复现最小场景作 RV 开/关；必要时由 1 敌增至 6 敌 | RV 贡献及规模关系，不预设敌人数无关 |

S2 若不能保持对照，改用同批原生素材、同一视野场的受控回放；它只证局部机制，最后仍需原生游戏验证。S4 再用同轨迹回放互证，不能把少了碰撞特效后的改善全算给视野。首个最小对照做正反顺序；没症状或计数阳性就如实记未复现，不无限重跑。

### P0-c 每帧最少记录

- 统一帧号/时间轴；整帧、RV、原生、其他监听及呈现后区间。看 >50ms、>100ms 次数和连续慢帧长度，不只等 >100ms 才算卡顿。
- 实际眼点、上次计算点、身体位置，computeFov 触发原因位集、视口/墙光代次、命中及击退事件。godMode 下掉血可能复位，不能仅靠帧末 hp 判命中。
- 按玩家弹体/敌方弹体/其他特效分组，记录外框与支持面积、全亮/全暗/混合状态；新 raster、范围改变、版本失效、输入相等、模糊、Shape 重画和 mask 重绑分别计数。
- 敌人总数、部分可见数、状态切换、外框变化及重建。分配量与内存净变化分开，不凭内存下降认定 GC 根因。
- 用内存缓冲、窗末落盘，不逐帧截图/写文件；视觉验证单独跑。`applyVision` 内含 `fillFogCache`，`hideEnemies` 内含 `applyWorldVisuals`，不得叠加父子耗时。

产出一张“条件→症状→分段成本→实际触发计数”表及可重放最小场景，够选择下一候选即可，不强制完整普查。

## 5. 按归因推进优化

| 候选 | 进入条件与实现切口 | 护栏与退出条件 |
|---|---|---|
| C4-exact：保真减少场生成/墙体更新 | H2 主导时，先分解 fillFogCache 的角点射线、混合格细算、写图/滤镜，以及墙体输入扫描/材质更新。只试主要部分的一项改动：同起点同遮挡同设置才复用采样，显示输入完全相同才省重绘 | 移动起点不沿用旧角点；门窗、窄缝、记忆、亮度变化即时处理。比较/维护成本抵消收益即退出，已失败的全图区域版本方案不原样重做 |
| C1-adaptive：复用有收益的弹体区域 | H1 主导且同输入重复请求确实多时，评估仅对高复用区域用粗格缓存，高失效率走原精确范围。记录命中、扩张像素和生命周期成本 | 既有 2×2 C1 不直接部署。范围扩大须保持原采样相位及支持区；移动、破墙、新弹体即时补齐；持续绑定最终像素相同 |
| C5-local：敌人局部遮罩 | S3 复现且掩膜占主要成本时，先减少相同输入的重复外框/材质工作，暂不统一两套缓存 | 动画换帧、旋转、长枪、血条、渐入须保持。旧重载窗部分可见敌人为 0，不足以启动缓存重构 |
| C2/C3/C4-a：画质或时序选项 | 保真收益不足后，再比较弹体边缘简化、有限显示降频或视点刷新降频；各有开关和示例 | 未经用户接受不默认启用，不宣称运动中不可察觉；不得破坏亮处弹迹或延迟逻辑可见性导致暗敌泄漏 |

小位移不等于阴影小变化：贴近墙角时眼点少量移动也可能使远处边界大幅偏移。旧“2–3 帧≈50ms、额外只有几像素”的承诺撤回。历史夹具为 30fps，一帧约 33.3ms；等待 2–3 帧约 67–100ms，低帧率时更长。若日后选择降频，须定义毫秒上限、紧急刷新条件以及可见性/探索语义，不只定帧数。

现有 `vision_quality_preset=2` 也非无条件覆盖单项配置：显式单项键优先。新增开关须能准确恢复旧算法，不能只承诺改预设即可撤销全部变化。

直接 Bitmap 替代、改变 cacheAsBitmap 语义、重叠合罩、批量预绘、整图区域版本和无依据池化等旧失败实现不原样重跑。若新证据能排除原失败条件，再说明差异后研究；不据旧失败宣称保真空间穷尽。

## 6. 采用标准与交付次序

1. **正确性**：以当前正式语义为准。按候选影响覆盖首挂载/连续绑定、动态弹迹、长激光、门窗窄缝、墙角、敌人/血条/武器、渐入、换房/破墙/改设置。保真候选要求最终像素严格相同且分支实际命中，不用每帧摘罩重挂代替连续验证。
2. **性能**：同图同输入同配置、顺序交错、共同预热、同字节 A/A 控噪声。记录完整帧均值/P95/最大值/慢帧及局部耗时，逐窗看方向；核对发射、敌人行为、眼点轨迹。收益超过本批对照波动，不能靠少发弹或最后一窗异常得到有利均值。
3. **范围**：先验实际配置，影响 4/8 子格、current/classic 或非默认亮度时再补对应回归。图像、插桩归因、无插桩性能分开；局部回放不冒充完整游戏帧率。
4. **停止标准**：像素反例、分支没命中、输入变化、收益方向反复或尾部恶化无解释，均不采用；保留失败记录，一次推进一个有证据的候选。
5. **实施后的交付**：最小复现/归因表 → 候选补丁/对照 → 有收益且语义达标后走 remains-release-gate，备份、部署、回读指纹。C4-exact 的本次实施与边界见顶部报告；其他候选没有自动获得采用结论。

配置对齐与一项保真计算优化已完成。原症状下一步仍为 **S0/S1/S2 的空间对照**，再据结果进入 S3/S4；移动轨迹夹具不能代替敌人活动因果。当前授权不包含默认降低画质。
