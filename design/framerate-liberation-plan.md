# RealisticVision：大幅帧率解放方案（极小视觉微差换取流畅度）

> 文档编号：RV-DESIGN-20261102-PERF  
> 制定日期：2026-11-02  
> 状态：APPROVED_FOR_IMPLEMENTATION（已获用户明确授权）  
> 目标定位：通过微小、人眼极难察觉的视觉取舍，彻底打破 Flash/AIR 底层管线瓶颈，实现移动交火与密集场景的帧率大幅跃升。

---

## 1. 背景与核心设计原则

在 `v0.33.16-fx-fast` 中，我们将瞬态特效（子弹/火花/弹壳）由“逐帧矢量 Shape 模糊遮罩”改造为“中心点查表二值处理”，取得了立竿见影的成果（整帧耗时降 3%~9%，RV 调用开销降 34%~64%，固定开火 108ms 尖峰彻底清除）。

这证明了两个关键的底层渲染事实：
1. **Flash/AIR 的死穴在于 `DisplayObject` 上的动态遮罩（`cacheAsBitmap` mask）**：一旦大量对象（敌人、武器、粒子）挂载动态模糊遮罩，Flash 渲染引擎不仅需要在每帧对底层对象重新栅格化进临时位图，还要在 RENDER 阶段进行昂贵的逐像素 alpha 合成。
2. **全分辨率像素操作存在边际递减**：每帧对全屏大尺寸位图（如 1280×720）进行高斯模糊、`copyPixels` 和逐瓦片 64 条 DDA 射线检测，占用了极大的 CPU 内存带宽，而最终画面中阴影本身带有平滑柔化，过高的微观精度在动态游戏中并无肉眼可见的价值。

**设计原则**：
- **抓大放小**：从“微观算法抠毫秒”转向“管线级降维解构”；
- **视觉微差可控**：所有的视觉取舍均局限在动态交战中人眼不可察觉的平滑过渡带，保留核心光影氛围；
- **全档位可逆**：提供多级配置开关，玩家随时可一键切换回旧版 1:1 绝对画质。

## 2. 四大核心优化方案

### 方案 A：雾场半分辨率降采样管线（Half-resolution Fog Pipeline）——【渲染层核弹级削减】

- **现状瓶颈**：
  - 目前 `fogCache`、`fogRaw` 和 `fogBmp` 均按全图 1:1 像素生成。对于 48×25 瓦片（8×8 子格），位图尺寸达到 400×216 像素；全屏大地图甚至更大。
  - 每当玩家移动且视线更新时，需要在全尺寸位图上做 `fillFogCache` 写入、`fogRaw.copyPixels`、以及最昂贵的 CPU `fogBmp.applyFilter(..., curBlur)`（高斯模糊）。
- **优化设计**：
  1. 将内部雾场计算降低为 **1/2 分辨率**（瓦片子格从 8×8 降为 4×4，单瓦片 16 子格）；
  2. 核心缓冲区 `fogCache`、`fogRaw`、`fogBmp` 的宽高各缩减 50%（像素总量直接降至 **25%**，减少 75% 的像素操作量）；
  3. `curBlur` 高斯模糊滤镜的模糊半径等比例缩小（计算步长减半，CPU 高斯滤波开销降低约 70%）；
  4. 显示层将 `fogBmp` 挂载时设置 `fogBmp.scaleX = 2; fogBmp.scaleY = 2;`，并开启 Flash 原生的双线性插值平滑渲染（`smoothing = true`）。
- **视觉微差评估**：
  - 阴影边缘原本就有高斯羽化软边（`soft_current` 默认 20px）。1/2 分辨率的半透明暗色图在经过双线性拉伸 + 羽化后，边缘的渐变连贯度与 1:1 分辨率极为接近，没有明显的色阶断层或马赛克，在 1280×720 及以上动态分辨率下肉眼几乎无法分辨。
- **预期收益**：
  - 雾层 CPU 像素处理耗时与高斯模糊耗时直接减少 **70%~75%**；
  - 大幅削减显卡纹理上传与合成带宽。

### 方案 B：敌人身体遮罩容差二值化与肢体继承（Enemy Mask Fast-path）——【消灭骨骼重绘杀手】

- **现状瓶颈**：
  - 现版 `hideEnemies` 中，敌人包围盒只要有 1 个像素接触阴影，就会被判定为 `state=2`（挂载动态 Shape 遮罩，强制 `u.vis.cacheAsBitmap = true`）。
  - 骨骼动画或多肢体敌人在移动、开火时，Flash 每帧都需要将其重绘进内部位图，再与动态遮罩位图合成，交火场景中 6~20 个敌人同时遮罩是移动卡顿的核心元凶。
  - 狮鹫手臂（`visualGrifArm`）在 `applyWorldVisuals` 中独立遍历并执行 `applyWorldVisual`，重复走 `getBounds` 与遮罩生成。
- **优化设计**：
  1. **可见性面积门控（Visibility Ratio Gating）**：
     - 当敌人包围盒在当前视野场中的可见像素比例 $\ge 80\%$ 时，视为**完全可见（state=1）**：
       - 摘除 mask，关闭 `cacheAsBitmap`，允许原生矢量/位图直接渲染；
     - 当可见比例 $\le 15\%$ 时，视为**完全隐藏（state=0）**：直接设为不可见，省去所有遮罩逻辑；
     - 仅在 $15\% \sim 80\%$ 的真正半遮挡临界带才挂载动态遮罩。
  2. **从属肢体与手持武器状态继承**：
     - 彻底废除狮鹫手臂与手持武器在 `applyWorldVisuals` 中的逐对象 `getBounds` 与独立 mask 运算；
     - 手臂与武器直接继承宿主单位的可见性状态（宿主全亮则直绘，宿主全暗则空遮罩/隐藏）。
- **视觉微差评估**：
  - 战斗中，身处亮光下的敌人即使脚后跟或枪管尖稍微擦碰暗角，也不再出现轻微的局部边缘虚化，而是完整清晰呈现；这一变化不仅极难察觉，而且在战斗中更有利于快速索敌和瞄准反馈。
- **预期收益**：
  - 将多敌交火中同时激活 `cacheAsBitmap` 的敌人数量由 6~20 个压低到 0~2 个；
  - 彻底抹平多敌开火时的骨骼动画重绘尖峰。

---

### 方案 C：视锥体视口强裁剪与射线粗化（Frustum Culling & Fast Raycast）——【AS3 算力压缩】

- **现状瓶颈**：
  - `scenePaintBounds()` 针对小房间（$\le 48 \times 25$）存在历史遗留规则：强制返回整张地图（`0,0, spaceX, spaceY`），导致玩家在房间角落时，大量屏幕外不可见的瓦片依然在被逐一做射线与像素写入。
  - 边界瓦片硬编码 8×8 = 64 次 DDA `castRay` 探测，在视野边缘瓦片较多时单帧产生数千次光线遍历。
- **优化设计**：
  1. **取消小房间无条件全量重绘**：
     - 不论地图尺寸大小，一律根据摄像机当前视口范围（加上 4 格安全缓冲）裁切出严格的 `scenePaintBounds`；
     - 视口外的瓦片直接跳过 DDA 射线检测与位图像素刷新。
  2. **自适应射线粗化（结合方案 A）**：
     - 在 4×4 半分辨率网格下，单瓦片射线检测上限由 64 条骤减为 16 条（算力消耗直接降低 **75%**）。
- **视觉微差评估**：
  - 屏幕外未被绘制的区域只有在镜头移动过来时才会进入视口，加上外围 4 格的充裕缓冲，镜头平移时绝不会露出未绘制空隙；画质完全不受损。
- **预期收益**：
  - `fillFogCache` 脚本执行时间由 2.5~3.5ms 降低至 0.8~1.2ms。

---

### 方案 D：无损底座合并与内存抖动治理（Foundation & GC Anti-spike）——【消除孤立长帧】

- **现状瓶颈**：
  - 并行会话已验证并产出了成熟的无损优化代码，但尚未合入生产；
  - `currentSight.getVector()` 产生大数组分配、`BitmapData.compare()` 产生高频临时位图分配，引发底层垃圾回收（GC）周期性抖动（偶发 >100ms 停顿）。
- **优化设计**：
  1. **合入成熟无损优化**：
     - `coverage-fast`：敌人覆盖分类快速早退；
     - `paletteMap` 门控：底层光照未变时跳过墙面调色板整图上传；
     - `classic-repaint-v2`：classic 模式冗余重绘跳过。
  2. **消除高频堆分配**：
     - 复用预分配的全局 `Vector.<uint>` 缓冲区，杜绝每帧 `getVector` 的新对象分配；
     - 避免依赖 `compare()` 返回新位图的特性，使用高效的脏标记与版本号管理。
- **预期收益**：
  - 稳步压低基线整帧耗时 4%~7%；
  - 显著压减因 GC 造成的突发长停顿。

## 4. 验证门禁与回退保障

1. **同进程 A/B 回文性能测试**：
   - 使用 `build/fire-exhaustive` 自动化测试链，在真实 6 敌 / 24 敌移动交火、玩家原生开火场景下进行基准对照；
   - 严格统计平均帧间隔、P95、最大单帧以及 RV 阶段调用耗时。
2. **像素级视觉审查**：
   - 使用 Python PIL 脚本对实测场景截图像素进行亮暗结构比对，确保核心光影轮廓与明暗识别度符合预期。
3. **安全配置与即时回滚**：
   - 所有优化均受配置项受控管辖；
   - 保持完整的生产 SWF 备份，一旦发现任何严重视觉或逻辑异常，随时可通过改配置或还原 SWF 瞬间恢复。
